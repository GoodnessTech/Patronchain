## 2. Preflight Verification Checklist

Before executing any deployment on BOT Chain Mainnet, each item in the following checklist must be systematically verified and signed off:

### 2.1 Smart Contract Readiness
- [x] **Compiler Determinism**: Bytecode compiled with `solc-v0.8.24` and optimizer enabled (200 runs).
- [x] **No Vulnerabilities**: All known reentrancy, integer overflow, and front-running attack vectors addressed.
- [x] **Solvency Invariant Verified**: Contract balance strictly equals `accumulatedPlatformFees + sum(creatorBalances)`.
- [x] **Fee Cap Enforced**: Hardcoded invariant limits fees to $\le 10.0\%$ (`MAX_FEE_BASIS_POINTS = 1000`). Initial launch set to 2.5% (`250` bps).
- [x] **Checks-Effects-Interactions**: All state mutations precede external native transfers.
- [x] **Ownable2Step**: Protocol ownership requires explicit two-step transfer and acceptance.
- [x] **Pausable**: Emergency circuit breaker available in case of critical upstream infrastructure emergencies.

### 2.2 Operational Key Security
- [x] **Account Isolation**: Mainnet deployer key must be distinct from any testnet private key or test accounts.
- [x] **No Hardcoded Secrets**: Zero private keys or mnemonics exist in the repository source code, git history, or build artifacts.
- [x] **Air-Gapped / Hardware Wallet Support**: Recommended deployment via Ledger / Trezor or dedicated CI/CD secret manager with multi-signature governance.

### 2.3 Deployment Tooling Safety Guards
- [x] **Safety Guard 1 (Environment Confirmation)**: `scripts/deploy_mainnet.mjs` will strictly refuse to execute unless `CONFIRM_MAINNET_DEPLOYMENT=true` is explicitly provided.
- [x] **Safety Guard 2 (Chain ID Assertion)**: Script performs an on-chain query to `eth_chainId`. If the remote network returns any ID other than `677`, execution terminates immediately.
- [x] **Safety Guard 3 (Zero-Balance Check)**: Prevents failed gas burn by validating non-zero native BOT deployer balance before submitting transactions.
- [x] **Safety Guard 4 (Artifact Integrity)**: Verifies presence and structure of `artifacts/PatronChain.json`.

## 3. Deployment Runbook

### Step 1: Pre-Execution Environment Verification
Verify that your terminal environment has the required parameters:
```bash
# Verify RPC is responsive and confirms Chain ID 677
curl -s -X POST -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"eth_chainId","params":[],"id":1}' \
  https://rpc.botchain.ai
# Expected output: {"jsonrpc":"2.0","id":1,"result":"0x2a5"}
```

### Step 2: Set Deployment Credentials
```bash
export MAINNET_DEPLOYER_PRIVATE_KEY="0x<SECURE_MAINNET_PRIVATE_KEY>"
export CONFIRM_MAINNET_DEPLOYMENT="true"
export MAINNET_RPC_URL="https://rpc.botchain.ai"
```

### Step 3: Trigger Guarded Deployment
```bash
node scripts/deploy_mainnet.mjs
```

### Step 4: Validate Deployment Output
The deployment script will produce a verifiable record at `deployments/botchain-mainnet.json` with:
- Contract Address
- Transaction Hash
- Block Number
- Initial Fee Configuration
- Timestamp

## 4. Post-Deployment Verification & Launch Steps

1. **Verify Contract on Botscan**:
   - Navigate to `https://scan.botchain.ai/address/<DEPLOYED_CONTRACT_ADDRESS>`.
   - Submit the flattened source code or Standard JSON Input generated by `scripts/compile.cjs`.
   - Ensure green verification checkmark is visible.

2. **Verify Public State on Explorer**:
   - `platformFeeBasisPoints()` returns `250`.
   - `MAX_FEE_BASIS_POINTS()` returns `1000`.
   - `owner()` returns the deployer address.
   - `paused()` returns `false`.

3. **Configure Multisig / Governance Ownership (Recommended)**:
   - Call `transferOwnership(<MULTISIG_SAFE_ADDRESS>)`.
   - From the multisig account, submit a call to `acceptOwnership()`.
   - Confirm new owner on-chain.

4. **Frontend Production Switch**:
   Update frontend `.env` configuration:
   ```env
   VITE_ACTIVE_NETWORK=mainnet
   VITE_PATRONCHAIN_MAINNET_ADDRESS=0x<DEPLOYED_CONTRACT_ADDRESS>
   ```
   Rebuild production bundle and deploy static assets.
